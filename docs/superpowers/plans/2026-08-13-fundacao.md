# Fundação Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Colocar no ar um app Next.js com autenticação funcional (cadastro/login), banco Postgres, headers de segurança e CI — a base sobre a qual todos os outros subsistemas (banco de questões, prática, simulados, dashboard, redação, pagamento) serão construídos.

**Architecture:** Next.js 15 (App Router) + TypeScript, Postgres gerenciado pelo Supabase acessado via Drizzle ORM, autenticação via Better Auth (cookies de sessão httpOnly/secure/sameSite), validação de variáveis de ambiente com Zod, headers de segurança centralizados, deploy no Vercel. Testes de integração rodam contra um Postgres local via Docker Compose (localmente) e via serviço do GitHub Actions (no CI).

**Tech Stack:** Next.js 15, React, TypeScript, Tailwind CSS, Drizzle ORM, `postgres` (driver), Better Auth, Zod, Vitest, Docker Compose, GitHub Actions, Vercel, Supabase (Postgres gerenciado).

## Global Constraints

- TypeScript em todo o código novo (sem arquivos `.js`)
- Todo segredo (chaves de API, string de conexão do banco) só em variáveis de ambiente, nunca hardcoded — validadas com Zod na inicialização (spec: seção Segurança)
- Cookies de sessão devem ser `httpOnly` + `secure` + `sameSite` (spec: seção Segurança)
- Toda rota de API que exige usuário logado deve validar a sessão no servidor, nunca confiar em check feito só no cliente (spec: seção Segurança)
- Headers de segurança (CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, HSTS) aplicados a todas as respostas (spec: seção Segurança)
- ORM com queries parametrizadas — nunca SQL concatenado na mão (spec: seção Segurança)

```typescript
import { z } from "zod";

const envSchema = z.object({
  DATABASE_URL: z.string().url(),
  BETTER_AUTH_SECRET: z.string().min(32),
  BETTER_AUTH_URL: z.string().url(),
  NEXT_PUBLIC_APP_URL: z.string().url(),
});

export type Env = z.infer<typeof envSchema>;

export function parseEnv(source: Record<string, string | undefined>): Env {
  const result = envSchema.safeParse(source);
  if (!result.success) {
    throw new Error(
      `Variáveis de ambiente inválidas ou faltando: ${result.error.issues
        .map((issue) => issue.path.join("."))
        .join(", ")}`
    );
  }
  return result.data;
}

export const env: Env = parseEnv(process.env);
```

import { auth } from "@/lib/auth";

export async function GET(request: Request) {
  const session = await auth.api.getSession({ headers: request.headers });

  if (!session) {
    return Response.json({ error: "Não autenticado" }, { status: 401 });
  }

  return Response.json({
    id: session.user.id,
    email: session.user.email,
    name: session.user.name,
  });
}

- [ ] **Step 4: Criar o middleware de proteção de rotas**

Create `middleware.ts`:

```typescript
import { NextRequest, NextResponse } from "next/server";
import { getSessionCookie } from "better-auth/cookies";

export function middleware(request: NextRequest) {
  const sessionCookie = getSessionCookie(request);

  if (!sessionCookie) {
    return NextResponse.json({ error: "Não autenticado" }, { status: 401 });
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/api/me"],
};
```
